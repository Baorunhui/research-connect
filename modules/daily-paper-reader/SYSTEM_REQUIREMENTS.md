# 系统资源需求说明（System Requirements）

> 面向 fork 使用者：在部署之前，对照本文判断自己的机器是否适合，以及内存/显存/磁盘都花在哪里。
> 文中的内存/显存数字来自**单台实机测量**（Windows 11、NVIDIA T600 Laptop 4GB、dpr conda 环境），
> 供量级参考，非严格保证；不同硬件/系统会有出入。

## 一、先说结论：三种用法对机器的要求完全不同

| 用法 | 本机要求 | 说明 |
|---|---|---|
| **纯云端**（fork 默认） | 无任何要求，能开浏览器即可 | 定时流水线跑在 GitHub Actions 免费标准 runner（2 核 / 7GB 内存）上，本项目每日流水线即以此规格运行 |
| **本地轻量后端**（模型走远程） | 任意 4GB+ 内存的机器 | 召回（Supabase）、rerank、embedding 均调远程服务，本机只跑一个 ~40MB 的 HTTP 服务 |
| **本地 GPU 精排** | 显存 ≥4GB 的 N 卡（实测 4GB 可行） | fp16 权重占显存 ~1.2GB + 推理激活；系统内存峰值额外 +1.6GB |
| **本地 CPU 精排** | 内存 8GB+ 更从容 | 模型权重以 fp32 全部驻留系统内存（~3GB），不占显存；速度明显慢于 GPU |
| **本地抽图（可选）** | 上述 + 1.5GB 磁盘 | Docling 在独立的 `.venv-docling` 子进程环境，与主环境隔离 |

**判断口诀**：只用网页 → 无要求；本地跑流水线但模型走云 → 4GB 内存即可；想本地跑 reranker → 看显存有没有 4GB。

## 二·补、GitHub Actions 免费 runner（2 核 / 7GB 内存）上能跑什么

| 能力 | 在免费 runner 上的状态 | 说明 |
|---|---|---|
| CPU 精排（`local-qwen3-0.6b`） | ✅ **支持，手动触发可切** | fp32 权重 ~3GB，7GB 内存放得下；但 2 核推理慢——Step 3 从远端的几分钟变成约 1 小时量级。公共仓库 Actions 分钟数免费，花的是等待不是钱。手动触发日报流水线时把 Reranker 输入改为 `local-qwen3-0.6b` 即可 |
| 抽图（DocLayout-YOLO CPU 版） | ✅ **默认就在跑** | 每日流水线在 runner 上安装 CPU torch + `doclayout-yolo`，从 HuggingFace 拉取布局模型权重后推理；失败自动降级 PyMuPDF 兜底，不阻塞日报 |
| 完整 Docling 引擎（`.venv-docling`） | ❌ 未放入 runner，也无必要 | 1.5GB 独立环境仅在本地跑流水线时作为增强；CI 的轻量抽图链已覆盖主要场景 |
| 本地 GPU 精排 | ❌ runner 无 GPU | 标准免费 runner 没有 NVIDIA 卡，GPU 推理只能在本地 |

> 注意单任务上限：免费 runner 单 job 最长 6 小时。默认远端精排的整链约十几分钟，即使切 CPU 精排也远低于上限。

## 二、内存/显存都花在哪（实测画像）

| 组件 | 系统内存 | 显存 | 备注 |
|---|---|---|---|
| `local_server.py` 常驻 | ~36MB | — | 站点托管 + 全部 API 的宿主进程 |
| 日报 Step 3 本地 reranker（GPU + fp16） | +1.6GB 峰值 | ~1.2GB | 权重以半精度流式上卡；子进程，跑完即退出释放 |
| 日报 Step 3 本地 reranker（CPU 模式） | ~3GB 常驻至步骤结束 | — | fp32 权重全在内存；Windows 任务管理器可直接看到 |
| Step 2 embedding（默认远程服务） | 轻量 | — | 默认调用公益 embedding 服务，本机不加载模型 |
| 综述生成 Job | 数百 MB 内 | — | 进程内执行：召回 + 逐篇抽取 + 写作均为网络调用；PDF 深读全文落盘缓存，不占内存 |
| 论文总结 Job | 数百 MB 内 | — | 与日报同一套生成链 |

**常见误区**：任务管理器进程列表里的「内存」列**只统计系统 RAM，不含显存**。GPU 推理的进程照样会显示 1-2GB RAM（模型加载的中间副本与 CUDA 主机侧缓冲），这不是异常；显存要看「性能 → GPU」页或 `nvidia-smi`。

**高占用什么时机正常**：每日流水线的 Step 3（重排）运行期间出现 GB 级内存/显存是模型权重的正常画像；该步骤是独立子进程，结束后资源自动归还（通常几分钟内）。

## 三、磁盘占用（实测）

| 项目 | 体积 | 说明 |
|---|---|---|
| dpr conda 环境 | **5.2GB** | 含 CUDA 版 PyTorch；CPU 版 torch 会明显更小 |
| `.venv-docling`（可选） | 1.5GB | 仅本地抽图需要；`scripts/setup_docling.sh` 一键搭建 |
| `archive/` 运行产物 | ~43MB / 月 | 召回中间结果、运行日志，随使用累积 |
| `docs/assets/` 论文图片 | ~32MB / 月量级 | 日报抓取的论文图表 |
| `archive/survey_texts/` | 按需 | 综述深读的论文全文缓存，可随时删除（会自动重建） |

**建议预留**：纯云端用法 0；本地轻量 1GB；本地全链（含 GPU 环境与抽图）**10GB+**。

## 四、网络要求

本地后端模式需要能访问：

- **DeepSeek 或任意 OpenAI 兼容 API**（摘要、综述、总结的 LLM 调用）
- **Supabase**（论文库的 BM25 / 向量召回）
- **公益 rerank / embedding 服务**（`zwwen.online` 等，或换成 SiliconFlow / 自建）
- **GitHub API**（网页端工作流触发、Gist 分享）
- **arXiv / Jina Reader**（论文 PDF 与全文抓取）
- 本地模型模式下：**HuggingFace / ModelScope**（首次下载模型权重）

国内网络环境建议为 LLM 与模型下载配置代理或镜像（项目已内置多端点重试与清华 PyPI 源）。

## 五、自查当前占用

本地后端运行时，浏览器或 curl 打开：

```
http://127.0.0.1:<端口>/api/local/system
```

一次返回：本进程与子进程树（各自 RSS、命令行）、GPU 显存/利用率、运行产物目录磁盘占用、各 Job 驻留计数。排障时先看这里，一眼定位「内存被谁吃了」。

## 六、最低配置建议

- **只读日报 / 纯云端**：无要求（浏览器即可）
- **本地轻量后端**：2 核 4GB 内存，1GB 磁盘
- **本地 GPU 精排**：4 核 8GB 内存 + 4GB 显存 N 卡（实测底线；6GB+ 显存更从容），10GB 磁盘
- **无 GPU 但想本地精排**：16GB 内存（CPU fp32 推理 ~3GB 且较慢），可接受等待即可
