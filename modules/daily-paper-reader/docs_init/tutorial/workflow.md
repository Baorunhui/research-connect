# 推荐链路说明

本页讲解日报流水线的整体流程、三种运行模式的区别、每一步用到什么技术，以及最终推荐数量是怎么决定的。

## 整体流程

流水线由 GitHub Actions 定时触发（北京时间每天凌晨 02:30 左右），也可在站内手动触发：

```
抓取论文 → BM25 关键词召回 → 向量语义召回 → RRF 融合
        → Reranker 重排 → LLM 精炼打分 → 选择论文 → 生成日报文档
```

各阶段的作用：

| 阶段 | 作用 |
|------|------|
| BM25 召回 | 按订阅关键词做全文匹配召回 |
| 向量召回 | 用语义查询找主题相近的论文 |
| RRF 融合 | 把两路结果合成统一候选池 |
| Reranker | 对候选池精细排序打星 |
| LLM 精炼 | DeepSeek 给 0–10 相关性分并写中英文摘要 |
| 选择 | 高分论文进「精读区」，其余进「速读区」 |

## 论文是从哪里抓来的

论文库有**两条补充渠道**，日常运行时互为配合：

1. **数据维护层（多源定时入库）**：仓库里另有一组维护工作流每天定时抓取
   多个来源——arXiv（用官方 `arxiv` Python 客户端，默认只抓 cs 大类，避免
   全量 13 大类触发 arXiv 软节流）、bioRxiv / medRxiv / ChemRxiv、以及各会议
   （NeurIPS、ICLR、ICML、ACL 等）。抓到后**在本地用开源模型把标题+摘要编码成
   384 维向量**，连同元数据一并写入 Supabase 的论文表。
2. **流水线 Step 1（当天窗口抓取）**：主流水线启动时按所选天数窗口再抓一次
   arXiv 最新论文作为当日原始池。当你配置了 Supabase 且 BM25 + 向量两路 RPC
   都开启时，这一步会**自动跳过**——后续召回直接查数据库，不再重复抓。

所以对 fork 用户来说：配置好 Supabase 后，日常推荐的论文主要来自维护层
持续灌入的多源论文库；arXiv 抓取只是未接管时的兜底路径。

## 每一步跑在哪里：API 还是本地模型？

| 阶段 | 跑在哪 | 兜底方案 |
|------|--------|---------|
| BM25 召回 | **Supabase 数据库端**：PostgreSQL 全文检索（`ts_rank_cd`）打分排序 | 本地纯 Python BM25 索引（k1=1.5, b=0.75），中英文混合分词 |
| 向量召回 | **编码在本地，比对在云端**：查询向量由开源小模型 `BAAI/bge-small-en-v1.5`（384 维）在本地算出并缓存；相似度计算交给 Supabase 的 pgvector | 编码失败时全走本地模型重算 |
| RRF 融合 | **纯本地公式**：`score = Σ 1/(60+rank)`，融合两路排名后截断 Top-200 | 无需 |
| Reranker | **三通道可切换**：① zwwen.online / sinksilk 公益服务（CI 默认 `public-sinksilk-rerank`）② SiliconFlow API ③ 本地 `Qwen3-Reranker-0.6B`（CUDA torch）。只对语义型订阅词条生效，关键词词条不参与 | 重排不可用时回退 RRF 排名直接映射星级 |
| LLM 精炼与摘要 | **DeepSeek 云端 API**（0–10 打分、中英文摘要、精读长总结都是它） | 配置多个兼容端点自动重试 |

一句话总结：**检索类计算尽量下推到 Supabase 数据库端完成，语义编码用本地开源小模型，
只有需要"理解"的环节（重排、打分、写摘要）才花钱调用大模型。**

## 打分细则

一篇论文要被推荐，要先后经过两把尺子：

### 第一把：Reranker 星级（0–5★，相对分）

Reranker 给出的是**相对分数**：对每个订阅词条的候选池做最小-最大归一化后映射星级。
因此**每个词条的列表里必然有一篇 5★ 和一篇 1★**——星级高不代表绝对好，只代表
在这个词条内相对最相关。**≥4★ 的论文才进入下一轮 LLM 精炼**（约等于 RRF 归一化
0.5 分以上的头部候选）。

### 第二把：DeepSeek 0–10 分（绝对分）

DeepSeek 结合你的订阅需求描述给每篇打 0–10 分，档位含义：

| 分数段 | 含义 |
|--------|------|
| 9–10 | 直接命中订阅的核心需求 |
| 8–9 | 方法与需求强相关 |
| 6–8 | 方法不同但可迁移借鉴 |
| 3–4 | 仅边缘相关 |
| 0–2 | 噪声，不应出现 |

## 最终数量是多少？由什么决定？

从原始池到最终日报是一个逐层收窄的漏斗：

```
时间窗内全部论文（数千篇）
   ↓ BM25/向量召回，top_k = 50 + 每 1000 篇加 50，RRF 后截断 Top-200
候选池（≤200）
   ↓ Reranker 重排（池子随规模扩：30 起、每 1000 篇 +10、上限 120）
   ↓ 只保留 ≥4★ 进入 LLM 精炼
LLM 待评分集（几十篇）
   ↓ 按分数段选片（见下方名额公式）
精读区 + 速读区（通常十几篇）
```

**最终名额不是固定的**，核心公式是：

> 精读区：≥8 分论文全部进入（无上限）；速读区名额 = 模式基数 + 订阅词条数（tag_count）

精读保底数量也可以自定义：打开设置面板（本地服务设置 →「📊 每日推荐名额」），
可以修改精读区保底数量/速读区基数。≥8 分论文不足保底数量时，会从 6 分以上
按分数从高到低回填，保证精读区至少有保底数量篇（不会把 6 分以下的论文硬凑进来）。
留空则跟随当前运行模式的默认值。保存后写回 config.yaml，下次流水线生效。

| 运行模式 | 精读区保底数量 | 速读区基数 |
|----------|-----------|-----------|
| standard（默认） | 5 | 10 |
| extend | 10 | 15 |
| spark | 5 | 10 |
| skims | 不设精读区：LLM 分 ≥8 的全部放速读区 | — |

在此之上还有几条动态规则：

- **高分结转（carryover)**：≥8 分但当天没有进入精读/速读的论文会结转，最多保留
  5 天，第二天优先补位;
- **跨天去重**：已推荐过的论文不会因为重复出现而被再次选中（速览模式例外）;
- **同日多次运行合并**：同一天重复生成时按论文去重，标签取并集、分数取最高值、精读优先于速读。

## 触发入口与运行开关

1. 打开右侧 AI 问答面板，点底部 🚀 图标打开「快速抓取」弹窗；
2. 弹窗内可以选择：
   - **运行模式**：自动 / 标准精读 / 速览（全部进速读）；
   - **启用 Step 0 LLM 扩充检索关键词**（默认关闭）：运行前先让 LLM 根据
     订阅标签里的关键词扩充同义词、相关词再检索。开启会额外消耗一次
     LLM 调用，且改动的关键词会在下次运行重算向量缓存；
3. 点「立即搜寻十天内论文」或「立即搜寻三十天内论文」开始运行，
   进度可在运行面板分步骤查看。

以上两个开关的选择都会记住；也可以在 **⚙️ 设置面板**（本地服务设置）里查看和修改同一份默认值——运行模式、Step 0 开关、以及上一节的每日推荐名额都在那里，改完立即生效。

## 三种运行模式的区别

| 模式 | 触发方式 | 行为 |
|------|---------|------|
| **标准精读**（standard） | 模式选「标准精读」，或选 10 天快捷按钮（自动） | 正常分层推荐：高分论文进精读区，其余进速读区 |
| **速览**（skims） | 模式选「速览」，或选 30 天快捷按钮（自动） | 所有入选论文一律放速读区，不再区分精读；**忽略历史已读记录（seen_ids）**，同批论文可能重复出现 |
| **长窗口**（long-range） | 抓取窗口 ≥10 天时自动启用 | 运行产物用区间标识 `YYYYMMDD-YYYYMMDD` 归档，多次运行的结果合并在同一份区间日报里 |

补充规则：

- 「自动」表示不强制干预：10 天走标准精读，30 天走速览（后端对
  ≥11 天的窗口也默认转速览）；
- 手动强制可以打破默认组合，例如「30 天 + 标准精读」会生成一份
  大窗口但仍含精读区的日报，适合补追一个月内的重点方向；
- 长窗口不是独立开关，只要天数 ≥10 就自动生效，无需额外选择。

## 常见问题

- **为什么 30 天默认没有精读区？** 大窗口候选量大，默认使用速览以控制
  LLM 成本；需要精读区请把运行模式切到「标准精读」再触发。
- **勾了 LLM 扩充但没看到效果？** 扩充发生在 Step 0，看运行面板第 0 步
  状态即可确认是否执行；扩充后的关键词会写回配置并在下次运行生效。
- **同一篇论文今天又出现了？** 速览模式忽略已读记录，属于预期行为；
  切回标准精读即恢复去重。
- **今天推荐的篇数比昨天少？** 速读区名额取决于基数 + 订阅词条数；LLM 评分
  整体偏低（≥8 分少、6 分以上也不足）时，精读和速读都会相应变薄。
- **想每天全部精读？** ≥8 分论文已默认全部进入精读区；想保底更多篇数，
  把设置面板里的「精读区保底数量」调大即可。注意精读长总结会按篇调用 LLM，
  数量越大耗时和成本越高。
